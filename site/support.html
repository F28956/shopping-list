Getting connected

Shopping List needs no server and no account to be useful. It opens straight onto a list of its own, kept on the device. Nothing to enter, nothing to sign in to.

A server is what puts the same list on two devices, lets you share one, and lets a browser in. To use one, open Settings → Server and enter its address — something like https://lists.example.com — then sign in. On an iPhone, iPad, Mac or Watch that is Sign in with Apple; on Android and in a browser it is Google. Whatever the app was already holding is carried up to the server, so you lose nothing by having started without one.

Changing to a different server later signs you out and clears the lists cached on the device, because those belong to the old one.

When something is wrong

“This account may not use this server”

You signed in successfully, and the server does not admit you. This is not a mistake you can fix from the app — whoever runs the server decides which addresses may sign in. Ask them to add yours, then sign in again.

The app cannot reach the server

  • Check the address for a typo, and include https://.
  • If the server is on your home network, the phone has to be on that network too. An address like localhost means the phone itself and will never work.
  • The app accepts https:// only. The token in every request is a bearer credential, and on plain HTTP it travels in the clear — so this holds for a home network too. The server can get its own certificate; whoever runs it should turn that on.
  • A certificate from a private authority is not trusted just because it is installed on the phone. Android has not trusted user-added authorities for app traffic since Android 7, which looks like “the certificate is wrong” when in fact nobody asked the app to trust it.

Changes made in the shop have not appeared elsewhere

Adding and ticking off work with no signal at all — the changes are kept on the device and go up when it can reach the server again, and the app says at the top of the screen when it is in that state. If it stays that way once you are back on a network, the server is the thing to check.

Sending a log

Under Settings → Diagnostics the app can record what it is doing and hand it to you as a zip to attach to a report. The watch has no screen for this; its log comes out through the paired iPhone.

Off still records failures, which is usually enough, and is the setting to leave it on. Basic adds what happened — which request, how long it took — and still records nothing about what is on your lists. Detailed and Everything do record the names of your lists and everything on them; the app asks you to confirm before turning either on. The log stays on the device until you delete it, but if you send it to somebody you are sending them your shopping. Turn it back off when you are done.

The watch shows nothing

The watch app asks the paired iPhone for the credential and the server address. Open the app on the phone once, then try the watch again.

A share link does not work

Share links are good for one person and seven days. Once somebody has used a link it grants nothing to anybody else, including someone already on the list. Ask for a fresh one.

Running the server

The server is a single binary with a single SQLite file beside it, and it can get and renew its own HTTPS certificate — so there is nothing else to install. It prints a claim code at startup while nobody owns it; whoever signs in with that code becomes the owner and can then admit everybody else by email address. Removing an address ends that person's session on their next request. Full instructions are on the install page.

Deleting your data

If you use no server, your lists are a file inside the app: deleting the app deletes them, and nothing was anywhere else. Otherwise, ask whoever runs the server to close your account — that removes your lists, items, notes and purchase history. If you run the server yourself, the whole database is one file you control.

A diagnostic log, if you turned one on, is separate and stays on the device until you delete it, under Settings → Diagnostics.
