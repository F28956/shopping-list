What it actually does

A shopping list is a small idea. These are the parts worth building carefully.

Type the line, get the item

2 kg apples is one line, not three fields. The number, the unit and the name are read apart on the server — so the browser, the phone and the watch all agree on what you meant.

It remembers what you buy

Add something once and it comes back measured and filed. Suggestions fade on a thirty-day half-life, so December's mulled wine stops leading the list in June.

Ordered like the shop

Categories carry the order you actually walk — produce first, frozen last. Aisle numbers would be more precise and are deliberately not used: they differ by shopping center branch and change without warning.

A shop is a basement with no signal

Add things and tick them off with no bars at all. The changes queue on the device and go up when you surface — and a tick you made offline is not undone by a stale answer from the server on the way back.

Useful before you decide anything

With no server configured the app keeps its own list on the device — the same parsing, the same categories, the same history, because it is running the server's own code locally. Point it at a real server later and everything you already had goes with you.

A link that spends itself

Share a list with one link, good for one person and seven days. Only its hash is stored, so a leaked backup hands out nothing.

Your own units and categories

Units and categories belong to the server, not to a list — renaming one renames it everywhere, and nobody's kilogram is different from anybody else's.

Whose server?

Yours, if you want one. A server is what puts one list on several devices and in somebody else's hands — until then the app needs no server at all.

It is one binary and one SQLite file, serving the browser and every app from the same process, and it can get its own HTTPS certificate. Sign-in is Apple's on Apple devices and Google's in the browser and on Android, so there is no password here to lose — but who may use the server is your decision, and neither of theirs.

  1. 01

    Run it somewhere you trust

    A spare machine, a home server, a small VPS. It binds one port and keeps one file.

  2. 02

    Sign in and claim it

    It prints a claim code at startup, where you are already looking. Whoever signs in with that code owns the server — so a port that is public for a minute does not cost you the box.

  3. 03

    Say who else may in

    Everyone else is a stranger until you name them. Take an address off the list and the session ends on the next request.

  4. 04

    Point the apps at it

    Enter the address under Settings → Server. What the app already had is carried over. Full instructions.
