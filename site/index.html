What it actually does

A shopping list is a small idea. These are the parts worth building carefully.

Type the line, get the item

2 kg apples is one line, not three fields. The number, the unit and the name are read apart on the server — so the browser, the phone and the watch all agree on what you meant.

It remembers what you buy

Add something once and it comes back measured and filed. Suggestions fade on a thirty-day half-life, so December's mulled wine stops leading the list in June.

Ordered like the shop

Categories carry the order you actually walk — perimeter first, frozen last. Aisle numbers would be more precise and are deliberately not used: they differ by branch and change without warning.

The list you last saw

Open the app with no signal and the last list is still there, and says so. Adding and ticking off still need the server to be reachable.

A link that spends itself

Share a list with one link, good for one person and seven days. Only its hash is stored, so a leaked backup hands out nothing.

Your own units and aisles

Units and categories belong to the server, not to a list — renaming one renames it everywhere, and nobody's kilogram is different from anybody else's.

Whose server?

Yours. One binary and one SQLite file, serving the browser and every app from the same process. Sign-in is Google's, so there is no password here to lose — but who may use the server is your decision, not Google's.

    Run it somewhere you trust

    A spare machine, a home server, a small VPS. It binds one port and keeps one file.

  2. 02

    Sign in and claim it

    The first person through the door owns the server.

  3. 03

    Say who else may in

    Everyone else is a stranger until you name them. Take an address off the list and the session ends on the next request.

  4. 04

    Point the apps at it

    Each app asks for the server address the first time it opens, and keeps it in settings where you can change it later. Full instructions.
